### Discogs SDK (https://github.com/Crate-AI/discogs-sdk)
**Description:** TypeScript SDK for Discogs OAuth 1.0a authentication and API access

**Open Source Details:**
- **NPM Package:** `@crate.ai/discogs-sdk`
- **GitHub:** https://github.com/Crate-AI/discogs-sdk
- **Contributors:** 2 (Ahmed Felfel + Govind Mohan)
- **Language:** TypeScript 100%

**Core Features:**
1. **OAuth 1.0a Authentication Flow**
   - Complete OAuth implementation
   - Authorization URL generation
   - Callback handling with verifier
   - Token management
   - Automated authentication with local server (for development)
   
2. **API Endpoints:**
   - User identity retrieval
   - Collection management
   - Search functionality (releases, artists, labels)
   - Higher API rate limits (authenticated vs. unauthenticated)

3. **Storage Service:**
   - Token persistence
   - Configurable storage path
   - Automatic token management

**Technical Architecture:**
- **Language:** TypeScript 100%
- **Authentication:** OAuth 1.0a protocol
- **API Design:** Promise-based async/await interface
- **Storage:** JSON file-based token storage
- **Development:** Built-in local server for OAuth callback (port 4567)
- **Configuration:** Consumer key/secret, callback URL, user agent

**Example Usage:**
```typescript
import { DiscogsSDK, StorageService } from '@crate.ai/discogs-sdk';

const sdk = new DiscogsSDK({
  DiscogsConsumerKey: "YOUR_KEY",
  DiscogsConsumerSecret: "YOUR_SECRET",
  callbackUrl: 'http://localhost:4567/callback',
  userAgent: 'MyApp/1.0'
});

// Automated authentication with local server
await sdk.auth.authenticate();

// Get user identity
const identity = await sdk.auth.getUserIdentity();

// Search for music
const results = await sdk.search.getSearchResults({
  query: "Dark Side of the Moon",
  type: "release"
});

// Get user's collection
const collection = await sdk.collection.getCollection({
  username: identity.username,
  page: 1,
  perPage: 50
});
```

**Why Built:**
- Needed for Crate.audio development
- No existing TypeScript SDK with OAuth 1.0a support
- Existing solutions lacked proper authentication flow
- Open-sourced to help other developers building music/vinyl applications
- Demonstrates ability to build developer tools and SDKs

**Technical Challenges Solved:**
- OAuth 1.0a implementation (complex signature generation)
- Token persistence and management
- Automated callback handling for development
- Type-safe API interface
- Error handling and timeout management (5-minute auth timeout)

## Philosophy & Approach

### On Building Software
- "If software doesn't save time, it's useless" (except games)
- Social media is "a bottomless time pit masquerading as connection"
- Build what you need, then recognize universal patterns
- Ship fast: MVP in weeks, not months
- Use tools that don't fight you (boring tech stack = proven tech stack)

### On Architecture
- Good architecture scales through simplicity, not complexity
- Real-time should be default, not an afterthought
- Content should live outside code (enables non-technical updates)
- Decouple systems with bridge tables for flexibility
- Source of truth matters: sync FROM, never TO

### On Automation
- Find repetitive patterns and codify them
- Automate 90% of routine cases
- Empower humans for 10% exceptions (edge cases, special situations)
- Build audit trails for transparency
- Trust emerges from transparency

### On Velocity
- "Speed kills" (the kind that kills projects before they see daylight)
- In startups, you have a small window that's closing
- Build fast or don't build at all
- Build in the margins: early mornings, late nights
- Know what to skip
